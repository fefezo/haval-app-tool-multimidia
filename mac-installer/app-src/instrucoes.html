Haval Installer — macOS

Instalação e atualização do app do multimídia do Haval H6, 100% offline, direto do seu MacBook.

O que é este pacote

Um app para macOS (basta dar dois cliques) que instala o HavalShisuku (seu fork) e o Shizuku na central multimídia do carro. O MacBook conecta no WiFi do carro, serve os arquivos pela rede local e o carro se instala sozinho — sem internet, sem domínios de terceiros. Tudo dentro do pacote tem hash verificado antes de rodar.

Nada precisa ser instalado no Mac — nem Python. O instalador usa ferramentas que já vêm com o macOS (curl, perl/ruby/python3 — o que existir). Funciona 100% offline, inclusive na garagem sem sinal.

Instalação — passo a passo

1. No Mac: baixar e descompactar

  1. Baixe o arquivo Haval-Installer-macOS.zip do Google Drive (no Mac).
  2. Confira a integridade antes de descompactar — abra o Terminal e rode: 
    shasum -a 256 ~/Downloads/Haval-Installer-macOS.zip
    O hash exato é informado junto com o download. Se o valor não bater, o arquivo chegou truncado (download incompleto) — baixe de novo.
  3. Dê dois cliques no zip para descompactar. Você verá a pasta com Haval Installer.app e o PDF.
  4. Mova o Haval Installer.app para onde preferir (ex.: Downloads ou Applications).
Se o Finder disser “arquivo danificado ou incompleto”: o download veio truncado — repita o download e confira o hash do passo 2. Se mesmo com o hash correto o Finder recusar o zip, use a versão Haval-Installer-macOS.tar.gz (mesmo conteúdo; o descompactador nativo lida melhor com ela) ou extraia pelo Terminal: tar xzf Haval-Installer-macOS.tar.gz.
O Google Drive falhou 2× baixando este arquivo (109 MB). Pare de brigar com ele: copie o arquivo para um pendrive (qualquer um serve, são 109 MB) e leve ao Mac — ou transfira pela rede local (no PC: python -m http.server 8000 na pasta do arquivo; no Mac, Safari em http://IP-DO-PC:8000). Transferência local é rápida e não tem download pela metade.

2. Primeira abertura: liberar o macOS

Como o app não é assinado por um desenvolvedor registrado, o macOS pode recusar a primeira abertura. Faça assim:

Se aparecer “não é possível abrir porque o desenvolvedor não é identificado”:
Clique com o botão direito em Haval Installer.app → Abrir → Abrir novamente na janela de confirmação. Isso libera o app de vez.

Alternativa pelo Terminal: xattr -dr com.apple.quarantine "Haval Installer.app"

3. No carro: preparar

  1. Ligue o carro (acender a central é suficiente).
  2. Na central: ative o WiFi / hotspot (Ajustes → conexões do veículo).
  3. No MacBook: conecte ao WiFi do carro (a central é o gateway 192.168.33.x). Não use o WiFi de casa nem o do celular.

4. Rodar o instalador

  1. Dê dois cliques em Haval Installer.app.
  2. Abre uma janela do Terminal com um menu: 
      1) Instalacao completa (primeira vez no carro)
  2) Atualizacao rapida  (mesma assinatura, so o APK)
  3) Teste offline      (verifica arquivos + servidor, sem o carro)
  4) Simulacao completa (mock do carro - dry-run, sem hotspot)
  3. Digite 1 e tecle ENTER. Aguarde — o APK tem ~115 MB e a transferência pela rede do carro leva alguns minutos.

Testar antes de ir para o carro (opcional, mas recomendado)

Sem o carro por perto, use as opções 3 e 4 — funcionam sem internet e sem hotspot:
3 (Teste offline) verifica o servidor interno e baixa cada arquivo do pacote, conferindo o conteúdo byte a byte. Se passar, o pacote está íntegro.
4 (Simulação completa) roda a instalação inteira contra um “carro falso” dentro do Mac: verificação de hashes, transferência com conferência de tamanho e nova tentativa automática, pm install, modo B com hook via Frida e conferência de UID, tudo com respostas simuladas. Se terminar com MODE A succeeded ou MODE B succeeded, o fluxo está correto do início ao fim.

5. O que é sucesso

No final deve aparecer algo assim:
[+] MODE A succeeded - app UID 12345 (<= 10999, telnet at boot will work).
[+] Done! Mode A. Both packages should be installed:
…ou, se a central bloquear a instalação direta:
[+] MODE B succeeded - app UID 12345.
[+] Done! Mode B. Both packages should be installed:

O script instala o Shizuku e o app e depois verifica de verdade: os dois pacotes presentes e o UID ≤ 10999 (necessário para o telnet root do app na inicialização). Nesta central o Shizuku costuma ser bloqueado na instalação direta (beantechs disallow apk moe.shizuku.privileged.api) — o script então automaticamente usa o modo B: inicia o Frida, injeta o hook no system_server, confirma que o hook carregou (tentando de novo se necessário) e reinstala. Você não precisa fazer nada, é só esperar.

6. Reiniciar a central

Desligue e ligue a central (ou aguarde o próximo boot do carro). No boot, o app inicia sozinho (BootReceiver), conecta no telnet local (localhost:23) e sobe o Shizuku.

Atualizações futuras (quando você tiver uma ideia nova)

  1. Gere o novo APK no Windows (.\build.ps1) e republique o zip no Drive (mesmo fluxo deste documento), ou apenas copie o novo APK para o Mac e:
  2. No carro: dê dois cliques em Haval Installer.app → escolha 2 (Atualizacao rapida).
Por que a opção 2 é rápida: o APK é sempre assinado com a mesma chave de depuração, então pm install -r atualiza por cima mantendo o UID e a assinatura — sem Frida, sem reinstalar o Shizuku, ~2 minutos no carro.

Solução de problemas

SintomaCausa / solução
gateway is 192.168.x.y, not the Haval hotspot O Mac está em outra rede (casa/celular). Conecte no WiFi do carro e rode de novo.
hash mismatch Algum arquivo veio corrompido ou foi adulterado — o instalador aborta de propósito. Baixe o zip novamente do Drive.
“arquivo danificado ou incompleto” ao descompactar Download truncado. Rode shasum -a 256 e compare com o hash do download; baixe de novo ou use o .tar.gz.
Erro de “python3 not found” / Python Não é mais necessário: o instalador usa perl (sempre presente no macOS) ou ruby/python3 se existirem. Rode a opção 3 do menu para confirmar.
“não é possível abrir porque o desenvolvedor não é identificado” Botão direito → Abrir → Abrir (ver passo 2).
Connection timed out O Mac não precisa alcançar o próprio IP — o pré-flight agora verifica via loopback (o hotspot do carro não roteia de volta para o próprio cliente, por isso o timeout era esperado e não é mais fatal). O que importa é o carro alcançar o Mac: se a transferência falhar no carro (SIZE-BAD repetido), o macOS bloqueou o servidor no firewall — na primeira execução ele pergunta “deixar python3 (ou perl) aceitar conexões?”: clique em Permitir. Se você perdeu o aviso: Ajustes do Sistema → Privacidade e Segurança → Firewall → permita python3/perl. Mantenha o MacBook acordado e perto do carro e rode de novo.
404 File not found / Some files did not transfer O hotspot do carro caiu ou o Mac dormiu no meio — o IP do Mac mudou e o carro pediu para o serviço errado. O instalador verifica cada arquivo no próprio carro (tamanho) e tenta de novo automaticamente; se falhar de novo, ele para antes de instalar qualquer coisa. Permita o firewall, mantenha o Mac acordado e rode de novo.
hook did not report ready O Frida anexou mas o hook não confirmou que carregou (rede lenta ou o runtime demorou). O instalador tenta de novo até 4 vezes — inclusive com o bundle original vendado — e só instala depois que o hook confirma. Se todas falharem, guarde o log do Terminal e revise a saída.
beantechs disallow apk moe.shizuku.privileged.api É o bloqueio esperado desta central na instalação direta — por isso o modo B existe. Se aparecer no modo B (com o hook já ativo), algo falhou no Frida: guarde o log.
MODE A falhou e o MODE B também Revise a saída no Terminal (o script mostra o UID e quais pacotes faltam). Provavelmente é necessário reinstalar do zero ou o APK foi assinado com outra chave.
Transferência demorando muito Normal: ~115 MB pela rede do carro. O script espera até 15 min para o download do APK. Não feche a janela.
O app abre mas o Shizuku não sobe no boot Verifique se o UID reportado na instalação era ≤ 10999. Se sim, reinicie a central por completo (power cycle).

Segurança

  • Nada é baixado na hora da instalação. Todos os arquivos estão dentro do app, no seu Mac — o carro puxa pela rede local.
  • Tudo é verificado contra um manifesto SHA-256 pinado antes de rodar; qualquer divergência aborta a instalação.
  • Os binários do Frida são byte-idênticos ao release oficial 17.2.15; o Shizuku é o release oficial v13.6.0; o script de hook é uma reescrita clean-room do original.
  • O telnet (porta 23) da central é um shell root na rede do carro — a senha do hotspot é o seu limite de exposição. Não compartilhe.
  • O script de hook manipula o PackageManagerService para forçar UID baixo e contornar um bloqueio de instalação da GWM — é isso que permite o telnet root do app na inicialização.
